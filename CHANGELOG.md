# Changelog

## v1.3.3 — 2026-10-29

### Виправлено

- Реальна зупинка сервісу займала близько 1,6 с, хоча бюджет кадрів був 0,4 с: сам запис 64-байтного кадру в `hidraw` на цій панелі блокує приблизно 50–75 мс, а паузи між кадрами цього не враховували.
- Анімація зупинки тепер адаптивна: перед кожним наступним кадром перевіряється `time.monotonic()`, і запис зупиняється за дедлайном. На повільному `hidraw` надсилається 2–5 кадрів замість 16.
- Бюджет 0,4 с тепер включає і паузи, і фактичний час запису; загальна зупинка вкладається у 0,5 с.
- Тест імітує повільний `hidraw` із затримкою 50–200 мс на кадр та перевіряє ліміт 0,5 с для `parallel` і `sequence`.
- Оновлено README та README.en.md.

## v1.3.2 — 2026-10-29

### Змінено

- Анімація зупинки тепер має жорсткий бюджет 0,4 с і ніколи не перевищує 0,5 с разом із записом кадрів. Замість довгого зворотного проходу, кількох блимів і пауз панель коротко спалахує й швидко згортається.
- Для `sequence` кадри зупинки рівномірно проріджуються до 20, щоб довга послідовність не розтягувала `systemctl stop/restart`.
- Тест анімації перевіряє сумарну тривалість зупинки для режимів `parallel` і `sequence`.
- Оновлено README та README.en.md.

## v1.3.1 — 2026-10-29

### Виправлено

- Паралельна анімація тепер малює один спільний контур навколо всієї панелі, а не окреме коло кожної цифри: ліва верхня грань `CPU1` → верхні грані всіх шести цифр → дві праві грані `GPU3` → нижні грані у зворотному напрямку → ліва нижня грань `CPU1`.
- Середні вертикальні сегменти та центральні `G` у контурі не використовуються.
- Обидві смужки ростуть паралельно з контуром; після завершення панель блимає всіма сегментами й переходить до телеметрії.
- Оновлено меню `install.sh`, README, README.en.md, roadmap і тест анімації.

## v1.3.0 — 2026-10-29

### Додано

- Паралельна анімація запуску та зупинки: усі шість цифр одночасно заповнюються по колу, обидві смужки ростуть разом із ними, наприкінці спалахують підписи й панель блимає. Це новий типовий режим.
- Режими анімації `parallel`, `sequence` (попередня поведінка — цифри по черзі) та `off`.
- Інтерактивне меню вибору анімації в `install.sh` (whiptail або dialog, з текстовим fallback), а також `--animation MODE` і `--no-tui` для автоматизації.
- Конфігураційний файл `/etc/1stplayer-rt-lcd.conf` із `ANIMATION=`; `lcd.py` читає його автоматично.
- Прапорці `lcd.py`: `--anim MODE`, `--animation MODE` (у тому числі через `=`) і `--no-anim`.

### Змінено

- `lcd.py` починає телеметрію одразу після анімації, без зайвої паузи.
- `install.sh` записує вибраний режим у конфігурацію під час встановлення; `uninstall.sh` видаляє її.
- Оновлено README, README.en.md, roadmap і тести.

### Виправлено

- Послідовний режим зупинки гасить смужки разом із цифрами; паралельний — проходить ті самі кадри у зворотному порядку, тож цифри й смужки згасають одночасно.

## v1.2.0 — 2026-10-29

### Додано

- Анімація запуску `lcd.py`: цифри по черзі заповнюються по колу, смужки завантаження ростуть зліва направо, усі підписи спалахують, панель блимає один раз — і починається телеметрія.
- Анімація зупинки: коло повторюється у зворотному напрямку, панель блимає й плавно гасне. Працює як для `Ctrl+C`, так і для `SIGTERM` від `systemctl stop/restart`.
- Прапорець `--no-anim` для запуску без анімації; у цьому режимі панель очищується під час виходу.
- Тест `tests/test_animation.py` перевіряє кадри старту/зупинки, блим і очищення панелі.

### Змінено

- `lcd.py` збирає кадри через спільні хелпери `_compose`/`_write_frame`; кадри телеметрії не змінилися.
- Оновлено README, README.en.md і CI.

## v1.1.2 — 2026-10-27

### Виправлено

- GPU-телеметрія більше не залишається нульовою, якщо сервіс стартував раніше за `amdgpu`. `lcd.py` повторно визначає CPU/GPU-сенсори під час роботи, коли початковий шлях був `None`.
- Пошук `gpu_busy_percent` тепер сканує всі `/sys/class/drm/card*/device/`, а не лише `card0`–`card3`.
- Якщо сенсор зник або шлях застарів після скидання GPU, скрипт скидає його та знаходить заново.
- Додано повідомлення в журнал, коли GPU-сенсори знайдено пізніше.
- Оновлено README та README.en.md.

## v1.1.1 — 2026-10-27

### Виправлено

- Автозапуск після перезавантаження: сервіс більше не чекає 90 секунд на `.device`-юніт `/dev/1stplayer-rt-lcd`, який не активувався, бо udev не додавав тег `systemd`. Прибрано `After=`/`Wants=` для device-юніта.
- `lcd.py` отримав режим `--wait`: сервіс чекає на появу дисплея після завантаження замість запису в неіснуючий вузол.
- Додано `StartLimitIntervalSec=0`, щоб `Restart=always` не зупинявся після серії невдалих стартів.
- `install.sh` робить `daemon-reload` до udev, не перериває встановлення через помилку udev і виконує `reset-failed` перед перезапуском сервісу.
- Оновлено системний і user-юніти, README та README.en.md.

## v1.1.0 — 2026-10-27

### Додано

- Автовизначення `hidraw`-вузла за USB ID `5131:2007` через `HID_ID` у sysfs.
- Пріоритет вибору пристрою: явний аргумент → `/dev/1stplayer-rt-lcd` → пошук за VID/PID.
- Інформативна помилка зі списком доступних `hidraw`-пристроїв, якщо дисплей не знайдено або знайдено кілька.

### Змінено

- Прибрано сліпий fallback на `/dev/hidraw3`: скрипт більше не надсилає кадри на випадковий HID-пристрій.
- Оновлено README, README.en.md і docs/PROTOCOL.md.

## v1.0.0 — 2026-10-27

Перший публічний реліз.

### Додано

- `scripts/lcd.py` — телеметрія CPU/GPU: температури на трьох цифрах, завантаження на 10-сегментних смужках.
- `scripts/lcd_sym.py` — бігучий рядок на шести 7-сегментних цифрах (латиниця, кирилиця, цифри).
- `scripts/unlock.py` — стрес-тест усіх сегментів із регульованою частотою та лічильником FPS.
- systemd-сервіс `1stplayer-rt-lcd.service` для автозапуску телеметрії.
- Опційний user-сервіс `1stplayer-rt-lcd.user.service`.
- udev-правило зі стабільним symlink `/dev/1stplayer-rt-lcd` і `TAG+="uaccess"`.
- `install.sh` та `uninstall.sh`, цілі `make install/status/logs/uninstall`.
- Документація: `README.md`, `README.en.md`, `docs/PROTOCOL.md`, `docs/SEGMENT_MAP.md`.
- Схема панелі та банер репозиторію.

### Відомі обмеження

- Завантаження GPU читається лише з `gpu_busy_percent` драйвера `amdgpu`.
- Карта сегментів перевірена на пристрої `5131:2007`; інші ревізії можуть відрізнятися.
- Автовизначення пристрою за VID/PID не реалізовано — використовується udev symlink.
